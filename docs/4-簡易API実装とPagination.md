# 第4問：簡易API実装とPagination


下記要件を満たす`Pull Request`を`feature`ブランチとして作成してください。

## 背景

一覧APIが雑に実装されており、仕様通りのJSONスキーマやページネーションが未実装です。  
フロントと連携できるAPIを用意します。  
また、API仕様を明確にするためにOpenAPIドキュメントを作成します。

## 要件

1. 指定されたエンドポイント（`/api/v1/posts` など）をRESTfulに実装する。
2. ページネーションを実装し、クエリパラメーター（`page`, `per_page`）で制御できること。
3. レスポンスはOpenAPI仕様に準拠したJSONスキーマに準拠する（`data`, `meta` を含む）。
4. 不正なパラメーターに対するエラーハンドリングを実装する。
5. APIのリクエスト/レスポンスに対する簡易的な統合テストを追加する。
6. OpenAPI 3.0仕様に従ったAPIドキュメント（YAMLまたはJSON形式）を作成し、`/api-docs`エンドポイントで閲覧可能にする。
7. swagger-uiなどのツールでAPIドキュメントが閲覧できるようにする。

## 追加要件（カーソルページネーション）

8. ページネーションは**`OFFSET/LIMIT`を使わず、キーセット（カーソル）方式**で実装する。`created_at`が同値の場合のタイブレーク（`id`併用等）も正しく扱うこと。
9. なぜOFFSET方式では行ズレ（重複/欠落）が起きるのかを`notes/4-pagination.md`に説明する。

## 追加要件（ページング中の整合性）

10. ページング途中でレコードが挿入・削除されても、重複・欠落が出ないこと。検証スクリプト（ページング中に行を挿入し、全件をちょうど1回ずつ取得できるか）を添えると加点。

## 受け入れ基準

- ページネーションがキーセット方式で機能し、`data`/`meta`を含むJSONが返ること。
- テストが存在し、パスしていること。
- OpenAPIドキュメントが生成され閲覧可能。
