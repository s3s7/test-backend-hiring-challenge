# 第9問：キャッシュ導入と無効化戦略

下記要件を満たす`Pull Request`を`feature`ブランチとして作成してください。

## 背景

特定エンドポイントのレスポンスが重く、キャッシュ導入で改善できる可能性があります。同時に不整合を起こさない無効化戦略が必要です。

## 要件

1. Railsのキャッシュ（Fragment/Action/低レイヤーのキャッシュ）いずれかを導入し、指定エンドポイントの平均応答を改善する。
2. キャッシュのTTLまたはイベント駆動の無効化戦略を実装する（例：関連モデル更新時にキャッシュを明示的に削除）。
3. キャッシュ導入前後の簡易ベンチ（wrk/ab等、ローカルで実行できるもの）を行い結果を`notes/9-cache.md`にまとめる。
4. 一貫性の問題（stale data）の緩和策を記載する。

## 追加要件（並行下での無効化）

5. キャッシュ無効化が並行更新時に取りこぼさないこと（更新とキャッシュ削除の順序・競合を考慮）。staleが残り得るケースとその緩和策を`notes/9-cache.md`に記載する。`GET /posts/feed`を対象に含めてよい。

## 受け入れ基準

- キャッシュ導入でレスポンス改善の証跡があり、無効化戦略が実装されていること。
