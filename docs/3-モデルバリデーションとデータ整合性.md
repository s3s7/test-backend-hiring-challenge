# 第3問：モデルバリデーションとデータ整合性


下記要件を満たす`Pull Request`を`feature`ブランチとして作成してください。

## 背景

アプリにはモデルのバリデーション抜けや重複許可、破損データが混在しており、例外や不整合が発生しています。

## 要件

1. 既存モデルに適切なバリデーションを追加し、不整合データが許されないようにする。
2. 必要に応じてDB側の制約（ユニークインデックス、NOT NULL等）を追加するマイグレーションを作成する。
3. 既存の壊れたデータを修正または安全に排除するRakeタスクを用意する（`rake app:fix_data` 等）。
4. 追加したバリデーションについての単体テストを追加する。

## 追加要件（照合順序）

5. `users.email`は一意制約がなく、照合順序の都合で`Admin@example.com`と`admin@example.com`が別ユーザーとして登録できてしまいます。**一意性ポリシーを定義**（大小無視で一意／厳密一致のいずれか）し、制約・照合順序で担保する。再現手順を`notes/3-validation.md`に記載する。

## 追加要件（TOCTOUと一意性の並行安全）

6. 一意な値（例：投稿の`slug`等）を導入する場合の**並行作成時の競合（TOCTOU）**に対応する。`validates_uniqueness_of`だけでは並行下で重複が通る理由を`notes/3-validation.md`に説明（ここまでは必須）し、余裕があればDBの一意インデックス＋`RecordNotUnique`のハンドリングで実装まで行う。

## 受け入れ基準

- テストが通り、Rakeタスクでデータ修正が行えること。
- マイグレーションによりDB整合性が強化されていること。
