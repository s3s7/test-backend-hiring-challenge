# 第20問：設計判断ドキュメント（ADR）とRCA（文章での説明）

下記要件を満たす`Pull Request`を`feature`ブランチとして作成してください。

## 背景

本試験はAIツールの活用を歓迎します。一方で、**自分の判断として説明できること**を最重要視します。
実装と同じくらい、**判断を言語化して他者（将来の運用者・チームメンバー）に伝える力**を評価します。本問は、その説明を**文書**で行うものです。

## 要件

1. **ADR（Architecture Decision Record）を1〜2件**作成する（`docs/adr/`配下）。
   - 例：第4問のページネーション方式、第13問のカウンター競合対策、第10問の認証方式など、自分が重要だと考えた判断を選ぶ。
   - 各ADRに「背景 / 検討した選択肢 / 決定 / トレードオフ / 却下した案とその理由」を含める。
2. **RCA（Root Cause Analysis）を1件**作成する。
   - 第11問のインシデントログ（同問の「追加要件」内に掲載）または第2問のフレーキーテストのいずれかを題材に、
   - 「事象のタイムライン / 根拠 / 根本原因 / 暫定対応 / 恒久対応 / 再発防止」を記載する。
3. 各文書で**想定読者・前提・未対応事項**を明示する。

> AIに生成させた箇所についても「なぜ妥当と判断したか」を、該当する `notes/<N>-*.md` 側で説明してください（「なぜ動くか分からない」状態は減点対象です。`notes/_TEMPLATE.md` の「判断・トレードオフ」欄を参照）。

## 受け入れ基準

- ADR・RCAが所定の構成を備え、**自分の実装・計測と整合**していること（数値や判断が実作業と食い違わないこと）。
- トレードオフと「却下した案」が言語化されていること。
- AI生成箇所を含め、**自分の判断として説明**されていること。

> 補足：評価軸は文章の綺麗さではなく、**判断の妥当性と、それが実装・計測と一致しているか**です。
