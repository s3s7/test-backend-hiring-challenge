# 第7問：バックグラウンド処理とリトライ設計

下記要件を満たす`Pull Request`を`feature`ブランチとして作成してください。

## 背景

長時間処理が同期で実行されており、Webレスポンスがブロックされています。ジョブ化して堅牢に処理を行う設計にします。

## 要件

1. 対象処理をActiveJob（Sidekiq等）に移行する。ジョブは再実行ポリシー（リトライ回数／間隔）を持つこと。
2. 失敗時の通知（例：失敗ログ、Dead Jobの記録）を実装する。
3. ジョブのインテグレーションテストを追加する（ジョブがキューに入ること、失敗時の挙動を検証）。
4. ジョブ導入によるトレードオフ（可観測性・遅延）を`notes/7-background-jobs.md`にまとめる。

## 追加要件（冪等性とトランザクショナルな投入）

`CommentNotificationJob`は通知カウンターを加算しますが、**再実行で二重加算**します（at-least-once配送前提で非冪等）。

5. ジョブを冪等化し、二重実行されても副作用が1回になるようにする。なぜ二重実行が起こり得るか、どう冪等化したかを`notes/7-background-jobs.md`に説明する。二重実行を再現したログを添付できると望ましい。
6. ジョブ投入は現状`Comment#save`後に`perform_later`しているため、**保存はコミット済みなのに投入が失敗する／投入したのにトランザクションがロールバックする**といった不整合（dual-write問題）が起こり得る。これを説明し、トランザクショナルな投入（`after_commit`もしくはOutboxパターンの簡易PoC）で緩和する。

## 受け入れ基準

- バックグラウンドジョブが機能し、失敗時の対処が確認できること。
