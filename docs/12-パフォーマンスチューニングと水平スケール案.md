# 第12問：パフォーマンスチューニングと水平スケール設計

下記要件を満たす`Pull Request`を`feature`ブランチとして作成してください。

## 背景

負荷試験でスループットが不足しており、スケール戦略やアーキテクチャ改善が必要です。
DBやキャッシュ、非同期処理を含めた設計が求められます。

## 要件

1. アプリケーションの負荷を簡易ベンチ（wrk等）で計測しボトルネックを特定する（ローカル小スケールで可）。
2. 解析結果に基づき、水平スケール可能なアーキテクチャを提案し、必要な変更を実装する（ステートレス化、セッション管理、外部ストレージ活用など）。
3. DB負荷低減のための設計（リードレプリカ、キャッシュレイヤー、CQRS案等）を提示し、簡単なPoCコードや設定を含める。
4. 変更後の負荷改善の比較データを`notes/12-performance.md`に記載する。
5. データ整合性や移行時のダウンタイム最小化案を短く記載する。

## 追加要件（メモリとカウンター）

6. `GET /posts/export`は全件をメモリにロードしており、データ量増加で**メモリが逼迫**します。`find_each`/バッチ＋ストリーミング応答へ改善し、何を・なぜ改善したかを`notes/12-performance.md`に記載する。改善前後のRSS（メモリ使用量）の数値を残せると望ましい。
7. `posts#show`の`views_count`のインクリメント（第13問参照）のような**並行下で壊れる箇所**を、水平スケール時に正しく動く形へ整理する（アトミック更新・ステートレス化）。

## 受け入れ基準

- ボトルネックの特定と改善案の実装があり、改善効果の説明があること。
