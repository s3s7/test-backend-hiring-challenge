# 第1問：開発環境の構築

下記要件を満たす`Pull Request`を`feature`ブランチとして作成してください。

## 背景

受験者がローカルやレビュー環境で確実に検証できるよう、アプリのDockerベースの開発環境と必須ツールの整備を行ってください。

### 現状、主に以下が不足しています

- `Dockerfile`がベストプラクティスな状態ではない
- `compose.yml`がベストプラクティスな状態ではない
- `rspec`がプロジェクトに導入されていない
- `rubocop`が導入されていない
- `reek`が導入されていない
- `Visual Studio Code`用の設定（`.vscode/`）がない

## 要件

1. `Dockerfile`をベストプラクティスな状態にしてください
2. `compose.yml`をベストプラクティスな状態にしてください
3. `rspec`を導入し、サンプルテストが実行できるようにする（失敗する事が想定される状態です）
4. `rubocop`と`reek`を導入し、基本的な静的解析がローカルで実行できるようにする
5. VS Code用の推奨設定を`.vscode/settings.json`に記載する
   - 推奨拡張を`.vscode/extensions.json`に明記すること
6. `notes/1-setup.md`に以下を記載すること：
   - セットアップ手順（レビュワーが再現できるコマンドの列挙）
   - 追加したファイルと理由の要約（`Dockerfile`、`compose.yml`、`.vscode`等）
   - 選定したツールや設定の短い理由（なぜそのバージョンや設定にしたか）

## 追加要件（Docker実技）

現状の`application/Dockerfile`・`compose.yml`は意図的にベストプラクティスから外れています（単一ステージ／root実行／不要パッケージ／キャッシュ非効率なレイヤー順／`.dockerignore`不在／`HEALTHCHECK`不在等）。

7. マルチステージビルド化、非rootユーザーでの実行、適切なレイヤー順とビルドキャッシュ活用、`.dockerignore`整備、`HEALTHCHECK`を行う。
8. `docker compose`でapp + MySQL（＋後続問題で使うSidekiq）が連携起動できること。
9. 何を・なぜ改善したかを`notes/1-setup.md`に記載する。改善前後のイメージサイズ・ビルド時間を計測して数値で残せると望ましい。

## 受け入れ基準

1. `docker compose build`と`docker compose up -d`で開発環境が起動し、アプリに接続できること。
2. コンテナー内で`bundle exec rspec`が実行できること
3. コンテナー内で`bundle exec rubocop`が実行できること
4. コンテナー内で`bundle exec reek`が実行できること
5. `.vscode/`の設定が含まれ、推奨拡張リストと簡単な利用方法が`notes/1-setup.md`に記載されていること
6. `notes/1-setup.md`に手順と変更点が明記されていること
