# 第2問：テストの全通


下記要件を満たす`Pull Request`を`feature`ブランチとして作成してください。

## 背景

リポジトリの `application/` は依存や設定が不完全で、CIでテストが失敗する想定です。  
受験者は環境を整え、テストをすべて通すことを目的とします。

## 要件

1. `README.md` のローカル起動手順でアプリが起動できるようにする。
2. `bundle install` → `bundle exec rake db:create db:migrate db:seed` → `bundle exec rspec` が動作し、テストがすべて成功すること。
3. テストが失敗している原因の特定と修正（テストコードを破壊的に変えずに修正すること）。

## 追加要件（フレーキーテストの根治）

テストには、**単体では通るがスイート実行・`--seed` 変更・`--order rand` で落ちる**フレーキーなものが含まれています。

4. フレーキーテストを特定し、**根本原因**（グローバル状態・実行順序依存・データリーク等）を突き止めて根治する。`sleep`/リトライ等の対症療法は減点。
5. 原因・修正内容を`notes/2-fix-tests.md`に記載する。**再現条件（落ちるseedや実行順）の提示は推奨**（根本原因の説明があれば必須としては可）。

## 受け入れ基準

- ローカル手順どおりに起動でき、`rspec` が全件成功すること。
- `notes/2-fix-tests.md` に実施内容（変更点の要約、発見した問題等）が記載されている事
