# 第17問：分散環境で正しいレート制限

下記要件を満たす`Pull Request`を`feature`ブランチとして作成してください。

## 背景

コメント作成やログインなどのエンドポイントが無制限に呼べるため、スパムやブルートフォースのリスクがあります。
本番ではアプリは**複数プロセス／複数インスタンス**で稼働します。

## 要件

1. 指定エンドポイント（例：`POST /comments`、`POST /login`）に**レート制限**を実装する。
2. **複数プロセス／インスタンスで正しく機能**すること。プロセス内メモリのカウンターは共有されないため不可。共有ストア（Redis等）で実装する。
3. **固定ウィンドウのバースト問題**（ウィンドウ境界で2倍叩ける）を理解し、スライディングウィンドウ等で緩和する。
4. 制限到達時は適切なレスポンス（`429 Too Many Requests`、`Retry-After`等）を返す。
5. **複数プロセスを想定した検証**（同時に複数ワーカーから叩いても合算で制限が効くこと）を行い、結果を`notes/17-rate-limit.md`に記載する。

## 受け入れ基準

- 単一プロセスだけでなく、複数プロセス想定でも合算でレート制限が効くことが検証できること。
- 固定ウィンドウのバイパス（境界バースト）への対策が説明・実装されていること。

> 補足：`rack-attack`等のgemを使う場合も、**バックエンドストアの選定理由**と**ウィンドウ方式**を説明できる状態にしてください。
