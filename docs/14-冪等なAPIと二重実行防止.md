# 第14問：冪等なAPIと二重実行防止（Idempotency-Key）

下記要件を満たす`Pull Request`を`feature`ブランチとして作成してください。

## 背景

コメント作成（`POST /comments`）は、保存後に`CommentNotificationJob`を投入し、副作用（通知カウンターの加算）を発生させます。
ネットワークリトライやユーザの二重送信、クライアントのタイムアウト再送により、**同じ操作が複数回実行され副作用が重複**します。

## 要件

1. 副作用を伴う作成系エンドポイントに**`Idempotency-Key`ヘッダー**を導入し、同一キーのリクエストは**何度送られても副作用が1回**になるようにする。
2. **同一キーの同時リクエスト（並行）**でも副作用が1回で済むこと。単純な「SELECTして無ければINSERT」では競合することを理解し、一意制約等で原子的に担保する。
3. 2回目以降の同一キーリクエストには、初回の結果（ステータス・レスポンス）を返す。
4. キーの有効期限・保管方法の設計判断を`notes/14-idempotency.md`に記載する。
5. 同一キー並行リクエストで副作用が1回であることを検証する統合テストを追加する。

## 受け入れ基準

- 同一`Idempotency-Key`での再送・並行送信で、副作用（通知カウンター等）が1回だけ発生することがテストで確認できること。
- 競合時の原子性の担保方法と、その理由が説明されていること。

> 補足：第7問（バックグラウンド処理）・第13問（並行性）と密接に関連します。ジョブ側の冪等性と合わせて整合的に設計してください。
